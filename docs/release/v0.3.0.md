# proxy-net v0.3.0 - Core

**Every forwarding decision, without a socket.** v0.3.0 builds the sans-IO core of proxy-net: the balancers, endpoint health, the retry budget, the checks a request passes before it is forwarded, head rewriting with the forwarding headers and `Via`, and the state machine that runs one exchange from the first pick to the last byte. None of it reads a clock or opens a socket; the caller feeds it facts and time. Forwarding over real sockets comes in 0.4.

## What is proxy-net?

A reverse proxy and load balancer for services on serve-net. It takes requests that serve-net has admitted, picks an upstream endpoint from a pool, and forwards the request there and the response back. Requests and responses are parsed strictly and written again, never passed through as raw bytes, and client-sent forwarding headers are always removed and rebuilt from the real client.

## What's in 0.3.0

- **Balancing.** Smooth weighted round robin, least connections, power of two choices, Maglev consistent hashing with a load bound, random, and first healthy. Round robin walks a schedule built once, in which each endpoint appears its weight's number of times with its turns spread evenly. The Maglev table is built from the endpoint addresses, so every node with the same configuration sends a key to the same endpoint; when an endpoint is ejected, only its keys move. Picks read atomics only.
- **Tiers and the panic threshold.** Higher tiers take traffic only when the tiers below have no healthy endpoint. When most of a pool is down, it balances over every endpoint rather than refusing everything.
- **Health.** Consecutive failures eject an endpoint for a time that grows with each ejection, up to a cap, and never more than the configured share of the pool at once. Active check results move endpoints between healthy and unhealthy with rise and fall counts. Each endpoint's state is one word updated without a lock.
- **The retry budget.** Retries in flight stay under a share of the pool's active exchanges (20% by default, at least 3), so a failing pool does not multiply its own load.
- **Request checks.** `CONNECT` and `TRACE` are refused, a body on `GET`, `HEAD`, `OPTIONS`, `TRACE`, or `DELETE` is refused, and paths that a proxy and an origin could read differently (`..`, `%2e%2e`, `%2f`, `\`, `..;/`) are refused, each unless the route allows it.
- **Head rewriting.** Hop-by-hop fields and every field `Connection` names are removed; the forwarding set is removed and `Forwarded` and `X-Forwarded-*` are written from the real client; `Host` follows the route's rule; header rules are applied; `Via` is added; a request whose `Via` names this proxy is refused as a loop. The proxy's own fields go in last, so a `Connection` option cannot remove them.
- **The exchange state machine.** Retries happen only for idempotent requests whose body is held, only before any response byte reached the client, and never after a timeout once the request was sent. A retry to an endpoint already tried waits first. Every state has a deadline.
- **Framing facts.** With `frame_facts(true)`, each upstream request carries a `proxy-frame` field stating how the proxy framed it, so an upstream that reads it can spot a framing disagreement. A client's `proxy-frame` is always removed.

## Changed

- proxy-net has its first dependency, the first-party `parse-net` (0.7, the version http-net 0.10 uses), for list parsing and for writing `Forwarded`.
- The `no_std` build now needs 64-bit atomics, for the lock-free balancers and health table. CI builds it for `aarch64-unknown-none` instead of `thumbv7em-none-eabihf`.

## Tested

- Unit tests for every function, integration tests for balancing (exact weights per cycle, tiers, bounded load, agreement between two nodes, minimal key movement), health (rise and fall at the thresholds, growing ejections, one ejection under concurrent failures), head rewriting (RFC 9110 and RFC 7239 cases), and attack tests for spoofed forwarding headers, bodies on `GET`, header injection, `Connection` abuse, ambiguous paths, h2c upgrades, duplicated POSTs, retry storms, and loops.
- Property tests of the exchange, path, and rewriting invariants.
- Six fuzz targets, three of them new (path checks, head rewriting, the exchange state machine), each run in CI.
- Linux, macOS, and Windows, on stable and 1.85.

## Known gaps

Nothing runs over sockets yet. The consistent-hashing key is fixed (all zero, so every node agrees); a builder setting for it comes in 0.4.

## Who should use it

Anyone embedding proxy-net's decisions in another engine, or testing a configuration's behaviour, can drive the core now.

## What's next

`0.4.0`: forwarding over real sockets through serve-net, the upstream connection pool, active health checks, and `proxy_net::proxy`.
