# proxy-net v0.4.0 - Forwarding

**proxy-net forwards real traffic.** v0.4.0 connects the sans-IO core to real sockets: a serve-net service on the inbound side, a pool of upstream connections on the other, and a forwarder that drives the core's exchange state machine between them. One line puts a listener in front of a set of servers.

```rust
let running = proxy_net::proxy("0.0.0.0:8080", ["10.0.0.1:80", "10.0.0.2:80"])?;
running.wait();
```

## What is proxy-net?

A reverse proxy and load balancer for services on serve-net. Requests and responses are parsed strictly and written again, never passed through as raw bytes; client-sent forwarding headers are always removed and rebuilt from the real client; paths that a proxy and an origin could read differently are refused by default.

## What's in 0.4.0

- **Tier 1.** `proxy_net::proxy(listen, upstreams)`: one pool, round robin, passive health, the default limits and timeouts.
- **`Proxy` and `Running`.** `ProxyBuilder::build` starts the running state: a balancer, a health table, a retry budget, and a connection pool per pool, and one health checker thread. `Proxy::serve` runs it on serve-net, and `Running` drains or waits.
- **The serve-net service.** `ProxyService` routes and checks each request before admission, so a refused request never costs an upstream connection. A small request body is held before an upstream connection is taken, so a slow client does not hold one; a larger body streams. The response streams back in parts, and serve-net asks for the next part only once the client has taken the last, so a slow client holds back the upstream, not memory.
- **Upstream connections.**
  - A pooled connection is reused only when its probe says it is open with nothing waiting, it is younger than the idle limit, and it has carried fewer than the most exchanges per connection.
  - A non-idempotent request takes only a connection used within the last second, so the keep-alive close race cannot lose it.
  - When an endpoint is at its connection cap, a request waits a bounded time, then gets a 503.
- **Retries.** Retries stay within the budget. A failure while connecting is retried for any method whose body is held, since the request never left the proxy; once a request may have reached the upstream, only idempotent methods are retried.
- **Health.** Active HTTP or TCP checks run on a schedule with jitter. Passive ejections end on time, and idle connections are closed past their limit, all from one thread that sleeps until the next job.
- **Desync tripwire.** Bytes an upstream leaves after a complete response close the connection, count against the endpoint, and are reported.
- **Observation.** An `Observer` with a method per event (route matched, endpoint picked, connected, retry, response head, exchange finished, health changed, refused, desync), and lock-free health and counter snapshots on `ProxyHandle`.
- **`hash_key`.** Sets the key consistent hashing uses for request keys. Set the same secret on every node to make the mapping unpredictable from outside.
- **The transport seam.** A `Connector` gives the proxy its connections. `TcpConnector` uses net-io; tests and tunnels can plug in their own.

## Changed

- A failure while connecting is now retried for any method whose body is held. In 0.3 only idempotent methods were.
- The upstream's `Date` is dropped from responses; serve-net writes its own.

## Tested

- Socket tests:
  - Round trips with rebuilt forwarding headers, and bodies of every size (chunked included).
  - A 2 MiB response streamed whole, and connection reuse.
  - Retries past a dead endpoint, a silent upstream answered 504, and a desynchronised upstream caught.
  - Ambiguous upstream framing refused, the refusals before forwarding, and active health checks taking a failing endpoint out.
- Socket-level attack tests. A recording upstream parses everything it receives with http-net:
  - Six smuggling vectors never reach the origin.
  - A request hidden in a body stays a body.
  - Pipelined requests are forwarded one by one.
  - A small body is held until it is complete.
- loom model checks of concurrent ejection, the ejection cap, and the retry budget.
- Seven fuzz targets, including a new one for whole exchanges against arbitrary upstream responses.
- Linux, macOS, and Windows, on stable and 1.85.

## Known gaps

- **Blocking workers only.** The service waits on the upstream inside serve-net's call, so it needs serve-net's blocking workers until serve-net can park a streamed reply. `Proxy::serve` and `proxy` set them.
- **Responses that lose detail until serve-net can send them:**
  - 103 Early Hints and trailers are dropped.
  - A response with more than 64 fields is answered 502.
  - A response with a known length is sent chunked.
- **Moved:** slow start moves to 0.5.

## Who should use it

Anyone who wants a proxy or load balancer in front of HTTP/1.1 servers on a trusted network can run it now. TLS to upstreams, WebSocket, and live reload come in 0.5.

## What's next

`0.5.0`: the WebSocket bridge, TLS and the PROXY protocol to upstreams, live reload and draining, service discovery, and slow start.
