# proxy-net v0.7.0 - Hardening

**Every threat in the model has an attack test.** v0.7.0 adds the rest of the attack suite, runs several proxies against each other, checks the bytes the proxy writes upstream against a second, independent parser, measures the memory an exchange holds, and puts the request path through 24-hour fuzz campaigns and soaks. `docs/SECURITY.md` has the threat model and every test.

```rust
// Behind a load balancer, with lean connections and the adaptive limit on:
let proxy = proxy_net::ProxyBuilder::new()
    .pool("app", proxy_net::Pool::new(["10.0.0.1:80"])
        .limits(proxy_net::PoolLimits::default().adaptive_concurrency(true)))
    .build()?;
let running = proxy.serve_with(
    "0.0.0.0:8080",
    proxy_net::Inbound::new().max_per_source(224).read_buffer(4096),
)?;
```

## What is proxy-net?

A reverse proxy and load balancer for services on serve-net. Requests and responses are parsed strictly and written again, never passed through as raw bytes; client-sent forwarding headers are always removed and rebuilt from the real client; paths that a proxy and an origin could read differently are refused by default.

## What's in 0.7.0

- **The full attack suite.** New socket tests for host routing, SSRF through routing, pool poisoning, memory exhaustion, topology leaks, interception, trailer injection, and cache poisoning. Every one of the 22 threats now has a named test, listed in `docs/SECURITY.md` with its defence and its cost.
- **Several proxies at once.** A chain of two adds each hop's `Via` once, in order, both ways; a loop between two ends with 508; an edge balancing over two inner proxies keeps serving every request when one stops.
- **The upstream bytes, read twice.** Requests built from arbitrary input go through the forwarder, and the bytes it sends upstream are read by http-net and by an independent strict reader written to RFC 9112. Both must accept them and agree on the method, target, every field, and the body, with no hop-by-hop or client framing field forwarded: 20,000 generated requests in CI, and a new fuzz target.
- **Memory per active exchange.** 27.3 KiB of heap by default; 15.3 KiB with `Inbound::read_buffer(4096)`, under the 1.0 target of 20 KiB. Smaller reads halve upload throughput per connection, so the default stays at 16 KiB.
- **An adaptive concurrency limit, as an experiment.** `PoolLimits::adaptive_concurrency(true)` answers 503 before an endpoint starts queueing. Over sockets, against an origin that serves 32 requests at once, with clients that wait after a 503: the same throughput as the default cap and p99 at 192 clients of 4.1 ms instead of 29.1 ms. With clients that retry at once, refusals turn into load, so it is off by default.
- **A soak harness.** Mixed traffic, a flapping origin, live endpoint changes every 2 minutes and a reload every 10, checked every minute and at the end for exchanges that never end, unexpected statuses, and heap growth.

## Changed

- serve-net 0.8.3: WebSocket messages queued for a client that is also sending no longer wait for the next ping. The two pipelined bridge tests, ignored in 0.6, run again: 20 of 20 runs each on Windows and on a loaded Linux machine.
- `EndpointHealth` has an `adaptive_limit` field (the struct is non-exhaustive).
- The comparison load generator counts refusals without closing the connection.
