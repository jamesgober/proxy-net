# proxy-net v0.2.0 - Design lock

**The API is written down, and the configuration is built.** v0.2.0 locks the public API of proxy-net in `docs/API.md`, with the version each part ships in, and ships the configuration surface: endpoints, routes and the compiled route table, pools and their policies, header rules, path safety, forwarding headers, and limits. Every setting is checked when the configuration is built, and every refusal names the pool, endpoint, route, or setting and what to change. Nothing forwards traffic yet.

## What is proxy-net?

A reverse proxy and load balancer for services on serve-net. It takes requests that serve-net has admitted, picks an upstream endpoint from a pool, and forwards the request there and the response back. Requests and responses are parsed strictly on arrival and written again on departure, so an upstream only sees bytes the proxy wrote, and client-sent forwarding headers are always removed and rebuilt from the real client address.

## What's in 0.2.0

- **Endpoints.** `Endpoint::parse` reads `host:port`, `ip:port`, and `[ipv6]:port`. Host names follow RFC 1123 and are stored in lowercase; IPv6 zones, userinfo, paths, an IPv4 address with a leading zero, and a port with a sign or a leading zero are refused, so every accepted endpoint has one reading. Endpoints carry a weight, a priority tier for failover, a connection cap, and a server name.
- **Routes.** Host patterns (exact, `*.example.com`, addresses, `*`), path patterns (`path("/api")` for `/api` and below, `path("/api/")` for below only, `exact`), methods, prefix rewrites, `Host` handling, request and response header rules, a path safety policy, and the methods allowed a body.
- **The route table.** `core::RouteTable::find` takes a `Host` value, a path, and a method, ignores case, ports, a trailing dot, and the query, and allocates nothing. Paths are matched as received, never decoded. A route that an earlier route shadows entirely is refused, since it could never match.
- **Pools and policies.** Balancing (round robin, least connections, power of two choices, consistent hashing with a load bound, random, first healthy), active health checks, passive health with a panic threshold, retries with a budget, timeouts, and connection limits, each with documented defaults and ranges.
- **Safe defaults, set now.** The forwarding set (`Forwarded`, `X-Forwarded-*`, `X-Real-IP`, and others) is removed from every request; header rules cannot touch fields the proxy writes itself; ambiguous paths (`..`, `%2f`, `..;/`) are refused by default; a body on `GET`, `HEAD`, `OPTIONS`, `TRACE`, or `DELETE` is refused by default.
- **No `std` needed.** With the default `std` feature off, the crate needs only `alloc`; CI builds it for a target without `std`.

## Tested

- Unit tests for every function and error path, data tables for endpoints, rules, and limits, and route matching checked against a separate reference matcher on 20,000 generated requests.
- Fuzz targets for endpoint parsing, route patterns, and route matching (the last against a reference matcher), with a 60-second run of each in CI.
- Linux, macOS, and Windows, on stable and 1.85.

## Known gaps

This version does not forward traffic. The sans-IO core (balancing, health, head rewriting, the forwarding state machine) comes in 0.3.0, and the serve-net service, the upstream connection pool, and Tier 1 `proxy_net::proxy` in 0.4.0. Until serve-net can park a streamed reply, the proxy will run on serve-net's blocking workers; `dev/PLAN.md` lists what proxy-net needs from serve-net, http-net, and net-io, with the fallback for each.

## Who should use it

Anyone planning a deployment can write and check its proxy configuration against the locked API now. Nothing here runs traffic.
